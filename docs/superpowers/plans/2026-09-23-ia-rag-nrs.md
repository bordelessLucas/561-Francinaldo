# IA RAG NRs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a more honest SST Vision analysis flow that uses a complete NR catalog, supports RAG-backed NR selection, and can return no visible issue or not-applicable reports without hallucinating risks.

**Architecture:** Keep image handling ephemeral and preserve the existing Expo + Netlify + Firestore flow. Add a versioned NR catalog shared by the app and backend, then evolve `AnalysisResult` and prompts so the model is allowed to return zero risks and must cite visible evidence and retrieved NR context.

**Tech Stack:** Expo SDK 57, React Native, TypeScript, Firebase Auth/Firestore, Netlify Functions, OpenAI Vision.

**Spec:** `docs-ia/sprint_atual_ia_rag_nrs.md`

## Global Constraints

- Keep Expo pinned to `57.x`; verify with `npm run check:sdk`.
- Analysis images remain ephemeral: no Firebase Storage write in the IA flow.
- Do not commit `.env` or expose `OPENAI_API_KEY` through `EXPO_PUBLIC_`.
- Use the official MTE NR page as source of truth for NR metadata.
- Do not implement voice or client UI changes until the IA/RAG acceptance criteria are implemented or explicitly reprioritized.
